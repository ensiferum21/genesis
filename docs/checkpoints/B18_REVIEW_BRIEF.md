# B18 review brief: concept invention (W09–W12)

The B18 exit is "typed concepts, explicit worlds and checked semantics". This brief is a
map written by the builder; every statement below should be checked against the code
and the evidence in `evidence/invention_b18/`.

## Reproduce

```
export GENESIS_TOOLCHAIN=/srv/toolchain PYTHONPATH=src PYTHONPYCACHEPREFIX=$(mktemp -d)
python3 -m unittest tests_formal.test_invention          # replays one package; root for the sandbox
python3 scripts/b18_invention.py /tmp/b18-rerun           # the full run, about an hour on 2 cores
```

`replay.json` records a replay of every package from its sources alone.

## What to check

| Question | Where to look |
|---|---|
| Is every representation proposal typed and bounded before it runs? Does its record state semantics, retained and lost information, cost and failure conditions? | `invention/representations.py` (`typecheck`, `proposals`); the `representations` field of the package |
| Are the obligations real Lean statements (image, soundness, dominance, loss), and are refuted ones DISPROVED with checked counterexamples? | `representations/package.json`: statements and their `lean` text |
| Does the method use only a Lean-checked sound representation, and does the domain checker validate every witness it returns? | `scripts/b18_invention.py` (`evaluate_representation`); `dev_evaluation.json` |
| Is consistency claimed only with a checked model, and inconsistency only with a checked proof of False? | `invention/worlds.py` (`judge`); `worlds/package.json` → `verdict` |
| Are transports refused when their conditions are unproved, when the target is inconsistent, or when the source is vacuous? | `judge`; `test_invention.Worlds` |
| Did recovery read only the snapshot, and is the recovered concept free of hidden constants? | `recovery/comparison.json` → `recovery.snapshot_tree_sha256`, `uses_hidden` |
| Are the four arms compared fairly, with the same recipes, budgets and statements and only the library different? | `recovery_experiment.extra_recipes_for`; `comparison.json` → `arms` |

## Known limits

- **W09.** The history library is generated by Genesis. It is not a Mathlib
  historical-cutoff study. The recovered concept equals Mathlib's `Antitone`
  definitionally, and the manual arm shows that.
- **W10.** The grammar has vertex-class decoders only. The DEV comparison picks the
  strongest baseline per task after the fact. No sealed evaluation exists.
- **W12.** World assumptions are predicates on hosts. `WD.Bipartite` fixes the vertex
  range so that it is decidable in Lean.
- **Proofs.** All proofs come from builder-written recipes (B17-OPEN-1).
