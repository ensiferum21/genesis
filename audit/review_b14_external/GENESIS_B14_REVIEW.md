Keep GV0 open. Treat this finding as a concrete extension of B14-OPEN-5, and qualify the broad assertion that unsupported claims are rejected. This review does not demonstrate a forged OPTIMALITY_CHECKED level, a bypass of independent release authorization, or a failure of the original R-01/R-02 fixes.

F-01 — false optimum wording survives bundle verification

Severity: high for the claim-reporting contract. Reproduced.

Use a four-vertex path with three edges. Its complete edge set contains no four-cycle, so its optimum is exactly three edges. An empty witness is valid but proves only a zero-edge lower bound.

B14 accepts the following sequence using its production API, without fixture keys, a custom trust registry, monkeypatching, altered archives, or proof-checker binaries:

1. Record the empty witness with value zero.
2. Create a mathematical problem with claim: "optimum" and value: 0.
3. Use the kernel-generated statement: “the optimum for c4_host_v2 host path4 […] is 0 edges”.
4. Promote the claim to WITNESS_VALID.
5. Build and verify its release bundle.

Observed output:

the optimum for c4_host_v2 host path4 [56e08d54c1cb2921] is 0 edges
actual_optimum = 3
effective_math = WITNESS_VALID
bundle_ok = True
problems = []

The witness label is accurate for the empty subgraph. The attached optimum statement is false. Successful bundle verification currently establishes neither truth of that statement nor adequacy of its wording.

Cause

• src/genesis/kernel/evidence.py, create_claim / math_statement (approximately lines 430–450): canonical text is generated from the requested proposition, including an optimum proposition. Canonical generation binds text to the requested value; it does not establish that value as optimal.
• The same file, _licensing (approximately lines 558–563): OPTIMALITY_CHECKED requires an optimum-shaped problem, but a witness-only promotion can still be attached to an optimum-shaped problem.
• src/genesis/release_bundle.py, wording_problems (approximately lines 124–126): every mathematical claim with a problem is skipped. This bypasses both statement and scope wording checks merely because the statement was generated by the kernel.

This extends the acknowledged B14-OPEN-5 limitation beyond a report using the bundle-wide ceiling: it also affects the generated mathematical statement inside CLAIMS.json.

Required repair and acceptance checks

Separate the requested proposition from the proposition established by evidence. An optimum conjecture may remain in historical/research records, but current exported wording must identify it as unproved unless matching checked bounds support it. A witness supports the corresponding finite lower-bound statement.

Remove the unconditional exemption for mathematical claims. Validate their current statement and scope structurally against their effective evidence. A keyword blacklist alone is not a sufficient semantic contract.

Add these regression cases:

• The exact false-optimum example below must be rejected as an asserted result, or exported explicitly as an unproved conjecture alongside only the supported lower-bound result.
• A correct finite lower-bound statement with a valid witness must remain exportable.
• An optimum statement with matching checked bounds must remain exportable.
• Revoking or losing the upper-bound evidence must downgrade the current wording, while retaining clearly marked historical records.
• Adding a different, valid optimality claim to the same bundle must not authorize stronger wording for this claim.
• Mathematical scope must remain confined to the checked problem; generated statement text must not exempt a free-form scope from validation.

Standalone reproduction

Run from the extracted B14 repository root with its dependencies available:

PYTHONPATH=src:. python - <<'PY'
from pathlib import Path
import tempfile
from genesis.common import code_identity
from genesis.graphs import check_witness, exact_checker
from genesis.kernel.evidence import EvidenceKernel
from genesis.models import GraphTask
from genesis.release_bundle import build_bundle, verify_bundle
from genesis.store import Store

with tempfile.TemporaryDirectory() as d:
    root = Path(d) / 'campaign'
    archive = Path(d) / 'release.zip'
    task = GraphTask(task_id='path4', n=4,
                     edges=((0, 1), (1, 2), (2, 3)), family='path')
    with Store(root) as store:
        store.set_state('source_hash', code_identity(Path.cwd())['sha256'])
        kernel = EvidenceKernel(store)
        task_hash = store.put(task.model_dump(mode='json'))
        payload = {'schema': 'genesis-witness-check-v2',
                   'task': task.task_id, 'task_sha256': task_hash,
                   'witness': [], 'value': 0}
        assert check_witness(task, ())['value'] == 0
        node = kernel.record('witness_check', payload,
                             route='genesis.campaign', source_hash='a' * 64,
                             verdict='VALID')
        problem = {'task_sha256': task_hash, 'value': 0, 'claim': 'optimum'}
        statement = kernel.math_statement(problem)
        kernel.create_claim('false-optimum', statement,
                            'this finite host only', [node], problem=problem)
        kernel.promote('false-optimum', 'math', 'WITNESS_VALID')
        print(statement)
        print('actual_optimum =', exact_checker(task)['value'])
        print('effective_math =', kernel.levels('false-optimum')['math'])
    build_bundle(root, archive)
    result = verify_bundle(archive)
    print('bundle_ok =', result['ok'])
    print('problems =', result['problems'])
    assert exact_checker(task)['value'] == 3 and result['ok']
PY

The final assertion confirms the vulnerable behavior on B14; a repaired implementation should invalidate that assertion by rejecting or safely representing the unsupported statement.
